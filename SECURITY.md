# Security Policy

## Supported Versions

Until 1.0, security fixes are considered on a best-effort basis for the latest
published 0.x prerelease. Older prereleases are not supported. There is no
supported package until the first release is published.

| Version | Supported |
| --- | --- |
| Latest 0.x prerelease | Best effort |
| Older prereleases | No |

## Reporting a Vulnerability

Do not report suspected vulnerabilities in a public issue. Use the repository's
[private vulnerability reporting](https://github.com/yellowmoonsoftware/RazQL/security)
flow by selecting **Report a vulnerability**. If that option is unavailable,
email [oss@yellowmoonsoftware.com](mailto:oss@yellowmoonsoftware.com).

Include, when possible:

- The affected version and environment.
- A description of the vulnerability and its potential impact.
- Reproduction steps or a proof of concept.
- Known mitigations or suggested fixes.
- Whether the vulnerability has been disclosed elsewhere.

Reports are reviewed on a best-effort basis, with no guaranteed response or
remediation timeline. Maintainers will communicate privately and, when a
vulnerability is confirmed, coordinate a fix and public disclosure.

Use public GitHub issues for ordinary bugs and other non-sensitive reports.
